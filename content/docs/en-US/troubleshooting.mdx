Almost every report lands on one of these. Before anything else, four checks resolve most of them.

## The bot does nothing

1. **The module is off.** Every module starts off and stays that way until you turn it on.
2. **The bot cannot see the channel.** A channel the bot cannot see is locked in every picker — if
   yours was selectable, this is not it.
3. **Tessera's role sits below** the member you are acting on. Position beats permission, always.
4. **The command is hidden from that member.** `/config` and the administrative commands are
   restricted by Discord itself, under Server Settings → Integrations.

## Roles are not being handed out

A bot only hands out roles **below its own highest role**. Roles above it are locked in the picker
for exactly that reason, so if the role was selectable and still is not given, check whether it moved
afterwards.

The bot log names the role it could not hand out, and says what to do: move its own role up, or
grant Manage Roles.

## The message does not go out, but everything else works

Almost always a **per-channel** permission: the role has Send Messages on the server and the channel
denies it. The module's test button is what answers this, because it really posts — the preview does
not.

If the message is an embed and comes out as plain text, **Embed Links** is missing in that channel.

## A slash command does not show up in Discord

Freshly registered names can take a minute to propagate, and Discord caches them per client.
Reconnecting the Discord client is faster than waiting.

If it never shows up for one specific person, it is permissions: Server Settings → Integrations →
Tessera.

## A save was refused

Someone else saved the same module while your page was open. Reload and look at the audit log — it
shows who, when and what changed — and redo your change on top of theirs. Nothing is lost, and
nothing is merged for you.

## A command ran and the answer was a refusal

That is the bot working. A refusal — role hierarchy, protected role, a bot as the target — is
answered with a readable message and counts as a **successful** run on the Commands screen. What
that screen counts as a failure is the bot breaking, not a moderator hearing no.

## The number on screen does not match what I see

| Number          | What it actually counts                                          |
| --------------- | ---------------------------------------------------------------- |
| _XP messages_   | Messages that **paid XP** — one per cooldown, not the total said |
| _Last counted_  | The last time they earned XP, not the last time they were around |
| _Entrants_      | Refreshed every five seconds; closing rewrites the final number  |
| _Commands used_ | Whole days in UTC, not the last 24 hours                         |

## The language is mixed up

By design, and they are three different things:

- **The command name** is always English.
- **The command description** follows the Discord client of **whoever is reading**.
- **What the whole server sees** follows the server language.
- **The reply only you can see** follows your own language.

The detail is in [Command reference](/docs/commands).

## If you host the bot yourself

Two privileged intents have to be enabled in the Developer Portal: **Server Members** and **Message
Content**. Without them the gateway connects and the events simply do not arrive — a silent failure,
not an error.
