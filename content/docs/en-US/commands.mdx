The list below is read from the bot's own catalogue, which is pinned against the payload sent
to Discord. A command cannot appear here without being published, and cannot be published
without appearing here.

A command only works when its module is on. `/config` is the exception — it is how you turn the
modules on, so it works whatever else is off.

## Who can run what

`/config` and the administrative commands are published with a required permission, so Discord
hides them from members who do not hold it.

<Callout tone="info" title="Permissions live in Discord, not here">
	To change who may run a command, open Server Settings → Integrations → Tessera in the Discord
	client. Tessera does not keep a second copy of that setting, so there is nothing to keep in sync
	and nothing that can disagree.
</Callout>

## Settings that hold a list

Some settings are not a value but a list — the roles handed out on arrival, the roles moderation
may not touch, the channels that pay no XP. A command option holds **one** value, so those do not
fit in an option.

They are edited through the `edit` option, which every `/config <module>` with that kind of field
offers:

```
/config welcome edit:Automatic roles
```

The command opens a **modal with Discord own picker** — the same list of roles or channels you
see anywhere else in the client. Whatever is already configured comes pre-selected, and the limit
of the field is enforced by the picker rather than by an error afterwards.

<Callout tone="info" title="edit goes on its own">
	Passing `edit` together with another option is refused. It opens a picker instead of saving right
	away, and accepting both would drop the other option in silence.
</Callout>

## What language the commands appear in

Two different things decide the language, and they are easy to confuse.

**The command name is always English.** `/config` is `/config` in every language — it is what you
type, and translating it would break every tutorial, screenshot and request for help.

**The description you see when you type `/` follows the reader's own Discord language.** We publish
each command in English and in Portuguese at once, and Discord shows each person their version. Two
members of the same server, one on an English client and one on a Portuguese one, read different
descriptions at the same moment — each in their own language. Discord resolves this before the
interaction ever reaches the bot.

**The server language governs what Tessera writes.** The welcome message, the level-up
announcement, the log channel embeds, the DM to whoever was punished, the ticket and giveaway
messages. Change it under **Settings → Server language**, or with `/config server language:`.

<Callout tone="info" title="I changed the server language and the descriptions stayed the same">
	That is expected. The server language does not reach the command descriptions, because they belong
	to Discord, not to us. To read the descriptions in another language, change your **own** Discord
	language under User Settings → Language.
</Callout>

## Subcommands

Several commands are a family rather than a single verb. `/config` takes one subcommand per
module, `/case` takes `revoke`, `/shop` takes `view` and `buy`. The **Commands** page in the
dashboard breaks each command's use down by subcommand, so you can see which part of a family
is actually being used.

## Where the counts come from

Every run is recorded with the command name, whether the bot answered, and how long it took.
The dashboard shows that per server over 7, 30 or 90 whole days in UTC — the same window the
overview chart uses, so the two never disagree about the same period.

A refusal is not a failure. When the bot answers _you cannot do that to a bot_, the command did
its job and is counted as a success. The failure column counts the bot breaking.
