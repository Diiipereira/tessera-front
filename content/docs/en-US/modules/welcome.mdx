Welcome listens for members joining and does two things, in this order: it applies the automatic
roles, then posts a message in the channel you chose. It is the only module with a required field —
without a channel it will not turn on.

## What happens when someone joins

Each step stands on its own. A role that could not be given does not stop the message, and a
message that could not be posted does not undo the role. Both failures reach the bot log with the
reason.

### Roles the bot cannot reach

A role is only given if it sits **below** Tessera’s role in the server list and the bot has
**Manage Roles**. Whatever fails is named in the log — the module does not swallow it, and it still
delivers the rest.

## What lands in the channel

Plain text, with an inline ping:

<Message
	content="Welcome to Test Server, @newcomer! Read #rules before you post."
	time="today at 2:02 PM"
/>

An embed carrying the same thing:

<Message
	embed={{
		color: '#5865f2',
		title: 'Welcome to Test Server',
		description: 'You are member number 431.\nRead #rules before you post.',
		fields: [
			{ name: 'Start at', value: '#introductions', inline: true },
			{ name: 'Questions', value: '#support', inline: true }
		],
		footer: 'Joined just now'
	}}
	time="today at 2:02 PM"
/>

<Callout tone="warning" title="Embed on means embed only">
	With **Use embed** on, the plain text is **not** sent alongside — the message is the embed. A line
	above the embed has to be part of the embed itself, or a ghost ping.
</Callout>

## Variables

Two of them, and they work in every text field of this module — the plain message and every part of
an embed: title, description, field names and values, author and footer.

| Variable   | Becomes                                     |
| ---------- | ------------------------------------------- |
| `{user}`   | The member who joined (ping or name, below) |
| `{server}` | The name of the server                      |

Anything the bot does not recognise stays written as it is instead of disappearing: a mistyped
`{usr}` shows up in the message, and that is how you notice.

## The three ping modes

| Mode       | What the member gets             | What `{user}` becomes in your text |
| ---------- | -------------------------------- | ---------------------------------- |
| **None**   | Nothing                          | The name                           |
| **Inline** | The ping inside the message      | The ping                           |
| **Ghost**  | A separate ping, deleted at once | The name                           |

The ghost ping exists to notify without leaving a permanent ping in the message: the bot posts the
mention alone, deletes it, and only then posts the greeting. In that mode `{user}` in your text
becomes the name — otherwise the member would be pinged twice and only one of them would vanish.

## Deleting the message later

The delay is in seconds, from 1 to 86,400 (one day). Zero and empty mean the same thing: it stays.

<Callout tone="info" title="The delay is counted by the bot process">
	If the bot restarts before the delay is up, that person’s message stays in the channel. It is the
	only consequence of a restart here, and it is a visible one — no record is lost.
</Callout>

## Commands

<Commands module="welcome" />

An embed does not fit in a command option, so it has a door of its own:
`/config welcome edit:Embed` opens a step-by-step builder inside Discord, with buttons for body,
author, images, footer and fields. The preview is the builder message itself. See
[Embeds](/docs/concepts/embeds).

## Testing without waiting for someone to join

The **Send test** button at the top of the screen posts the greeting in the configured channel using
you as the person who just joined. In Discord it is `/test module:Welcome`.

dashboard says which of the two it is.

## When it does not work

| Symptom                          | Likely cause                                                            |
| -------------------------------- | ----------------------------------------------------------------------- |
| Nobody gets greeted              | The module is off, or the **Server Members** intent is not enabled      |
| No message, but the role arrives | The bot lacks **Send Messages** there, or the channel is gone           |
| The embed comes out empty        | Every embed field is blank — an embed with no content is not sent       |
| The role is never given          | The role sits above Tessera in the list, or **Manage Roles** is missing |
| `{user}` shows up written out    | It is outside a module field, or the ping mode is a different one       |
