Logging listens for things happening in the server and posts an embed in the channel you chose
**for that event**. Every event has its own channel: messages can go one way and moderation
another, or everything to the same place.

## The fifteen events

| Group      | Events                                                        |
| ---------- | ------------------------------------------------------------- |
| Messages   | Message deleted, message edited, bulk delete                  |
| Members    | Join, leave, nickname changed, roles changed                  |
| Moderation | Ban, unban, timeout                                           |
| Server     | Channel changed, role changed, thread changed, server changed |
| Voice      | Joined a voice channel                                        |

An event is only posted when **the module is on, the event is on, and it has a channel**. Miss any
of the three and nothing goes out — and the dashboard test says which of the three is missing
instead of failing quietly.

## Who did what

Discord does not say, in the event itself, who caused it: a deleted message arrives without telling
you whether it was the author or a moderator. What knows that is Discord's own audit log, and it
arrives in a separate message — sometimes before the event, sometimes after.

The match is on **the key that changed**, not just the type: a nickname and a timeout are the same
audit entry on Discord, and what separates them is which member field moved.

<Callout tone="info" title="A ban does not become two lines">
	Banning also emits a member leave. When the leave finds a ban in the audit log it stays quiet —
	the ban event tells the story. A kick, on the other hand, shows up as a leave **with** a
	moderator.
</Callout>

Without **View Audit Log** the record still goes out, only without a name. It never stops going out
over this.

Fields are kept for what is genuinely long — content, before and after, roles, reason. The author
block carries the name and picture of whoever the record is about; the footer carries the id, which
is what you copy to investigate.

## Templates

Every event takes a template of its own: an embed you build, with that event's variables. An empty
template means the default embed — nothing has to be written for the module to work.

The `{line}` variable is the **whole default sentence**, available as a variable. That lets you
customise around it without rewriting what was already fine:

```text
{line}

If this was a mistake, ask the staff in #support.
```

Which variables exist is decided by the event itself: the screen offers exactly the ones that will
be substituted in that record, and the list changes from event to event.

## Preview and test

| Where               | Against what           | What it does                         |
| ------------------- | ---------------------- | ------------------------------------ |
| Preview on screen   | The draft              | Draws the embed, sends nothing       |
| The **Test** button | The **saved** template | Really posts in that event's channel |

The preview is built **by the same code that sends**, with sample data and in the server's language
— it is not a parallel drawing that can drift from the real one.

The test goes through the same door as a real record: module off, event off or event with no channel
answer _not ready_ without writing anything. It is disabled while the screen has unsaved changes,
because what goes out is the saved template.

<Callout tone="info" title="The test message says it is a test">
	A log channel is evidence, and a "Member banned" identical to a real one planted there would
	mislead whoever read it later. The test carries a line above the embed naming whoever asked for
	it, and that mention appears without notifying anyone.
</Callout>

Whoever clicks joins the sample cast: the test swaps the member and the moderator for you, the
channel for the destination channel, and picks a real role from the server — otherwise the Roles
field would come out empty in exactly the two events that exist to show roles.

## What was left out, and why

| Not logged                   | Reason                                                              |
| ---------------------------- | ------------------------------------------------------------------- |
| Avatar and username changes  | Discord does not list that event in the intents documentation       |
| Invites created and used     | Needs the `GUILD_INVITES` intent, which we do not ask for           |
| Reactions                    | Needs the `GUILD_MESSAGE_REACTIONS` intent, which we do not ask for |
| Channel and role permissions | The expensive part is diffing an overwrite readably, not listening  |

## When it does not work

| Symptom                           | Likely cause                                                  |
| --------------------------------- | ------------------------------------------------------------- |
| Nothing is logged                 | The module is off, or the event has no channel                |
| The record has no actor           | **View Audit Log** is missing                                 |
| A deleted message has no content  | Discord does not cache old messages — only recent ones        |
| A moderator gets the wrong credit | The correlation window is 10s; near-simultaneous actions blur |
| The template does not show up     | It is saved on another event — templates are per event        |
